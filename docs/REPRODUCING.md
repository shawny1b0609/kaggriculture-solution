# Reproduction guide

Run commands from the repository root. Python 3.11 and official
`kaggle-environments==1.32.7` are the supported baseline. The historical
development environment used NumPy 2.4.6, PyTorch 2.5.1, scikit-learn 1.8.0,
orjson 3.12.0 and threadpoolctl 3.5.0. CPU execution is sufficient.

## 1. Run the released agent

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/evaluate.py --seeds 0 908391002 --out results/local/selfplay.json
```

The release preparation reproduced cash **76,801 / 76,801** for seed 0 and
**136,450 / 136,450** for seed 908391002, with full production matching for
both seats. These are self-play regression checks, not estimates of online
win rate. Differences in engine versions can change mechanics or behavior.

The environment package can emit warnings while loading unrelated games.
The Kaggriculture process exit status and result checks determine whether
this test passed.

## 2. Build a submission

```bash
python scripts/package_agent.py --out dist/submission.tar.gz
python scripts/smoke_archive.py dist/submission.tar.gz
```

The archive contains the inference code, four required assets, license notices
and a content manifest. There are no raw replays or training dependencies.
Existing output files are not overwritten. The public archive differs from
the original 216-file submission because unused research files were removed
and private certificate provenance paths were redacted. The executed policy
is preserved; action parity is checked separately.

After reviewing competition eligibility and authenticating locally, you can
submit the generated archive through Kaggle's own submission interface. This
repository never loads or uploads your credentials.

## 3. Check exact actions against a reference

```bash
python scripts/check_parity.py data/reference_selfplay.json --out results/local/parity.json
```

Use a full reference game generated by this exact policy on both seats. The
checker compares every computed action with the action stored in the next
frame. An arbitrary opponent replay is not expected to match this policy.
The release preparation compared 1,438 actions with the original reference,
with zero differences. The 34 MB reference replay is not redistributed.

## 4. Rebuild compatibility certificates

```bash
python scripts/certify_crops.py --out results/local/crop_certificates.json
python scripts/certify_livestock.py --out results/local/pasture_certificates.json
```

The livestock check recovers 14 placements, seven eligible alternatives and
source totals of 192 milk / 170 wool. The output is diagnostic; it does not
automatically replace the frozen runtime assets.

## 5. Challenge a recorded-production opponent

```bash
python scripts/evaluate_contract.py --replay data/replays/episode.json.gz --source-seat 0 --save-contract data/compiled.json.gz --out results/local/contract.json
python scripts/evaluate_contract.py --contract data/compiled.json.gz --seed 123 --out results/local/contract_seed123.json
```

If `--source-seat` is omitted, the higher-final-cash source seat is selected.
The compiled contract preserves production and shop openings. The candidate
runs normally, and the opponent uses the baseline seller in the live market.
The runner checks source cash/material reconstruction and live accounting.
Output includes gross borrowing, outstanding debt, capacity losses, candidate
production matching and terminal margin. It stops on errors instead of
counting a broken opponent as a win.

This is a portable single-scenario entry point. For large experiments, use
separate output names, independent processes and an explicit manifest.
The scenario engine uses process-global hooks: do not run concurrent games
in threads inside one interpreter. See [evaluation design](EVALUATION.md).

## 6. Retrain only the market predictor

Follow [DATA.md](DATA.md). Training produces a new JSON model and error report,
not a new farm schedule. To test it, make a separate copy of the agent and
replace that copy's `g2/opponent_flow_v1.json`. Keep the released model and
historical evidence unchanged.

## Reproduction scope

The repository supports running the final policy, rebuilding the submission,
regenerating compatibility checks, processing supplied replays, retraining
the forecast and running native/contract evaluations. The historical full
168-game comparison also used six older agents and a specific online contract
corpus that are not all bundled. Its compact results are retained, but the
quick-start checks do not claim to rerun that entire historical experiment.
